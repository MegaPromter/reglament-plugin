# reglament-plugin — плагин настройки регламента разработки

Инструмент для Claude Code: мастер `/reglament-setup` разворачивает
в НОВОМ проекте систему управления разработкой — устав `CLAUDE.md`,
документацию-vault с регламентом, память ИИ, табло задачи и слой
принуждения из хуков-скриптов. Мультиязычный: язык проекта
выбирается первым вопросом мастера.

Репозиторий публичный: https://github.com/MegaPromter/reglament-plugin

## Регламент документации (средний вариант)

В этом репозитории действует ОБЛЕГЧЁННАЯ версия регламента: ведём
документацию и согласовываем решения, но без табло задачи и хуков
принуждения. Причина: репозиторий-шкатулка, код здесь — шаблоны для
других проектов, правки редкие и единоличные.

1. Документация — в `docs/vault/` внутри репозитория.
2. Перед задачей: сначала читать vault, потом код.
3. На любое требование — сначала проект заметки в чат, согласование,
   и только потом сохранение и код.
4. В коммите — ссылка на заметку (кроме мелких правок README и опечаток).
5. После выполнения — хэш коммита в заметку.
6. При сомнении — остановиться и спросить пользователя.
7. Принцип 10 (главный для этого репозитория): всё, что ассистент
   обязан делать регулярно, выносится в скрипт. Инструкция в тексте —
   временная мера до появления скрипта. Забыл шаг дважды — это повод
   написать скрипт, а не ужесточить формулировку.

Хуков и табло здесь НЕТ — принуждение держится на этих правилах.
Полный текст регламента, который мастер ставит в другие проекты:
`plugins/reglament/skills/reglament-setup/SKILL.md`, шаг 4.

## Структура проекта

```
.claude-plugin/marketplace.json      манифест маркетплейса
plugins/reglament/
  .claude-plugin/plugin.json         манифест плагина
  skills/reglament-setup/
    SKILL.md                         мастер настройки (основной файл)
    templates/                       ШАБЛОНЫ хуков для других проектов
docs/vault/                          документация этого репозитория
  задачи/                            заметки по задачам
```

Ключевое различие: `templates/` — это заготовки, которые мастер
копирует в ЧУЖИЕ проекты и переводит на язык проекта. Они не
исполняются здесь. Рабочих хуков в этом репозитории нет.

## Запуск тестов

Автотестов нет. Проверка шаблонов — вручную:

```
python -m py_compile plugins/reglament/skills/reglament-setup/templates/*.py
```

Поведение хуков проверяется прогоном на копии `.claude` настоящего
проекта (см. заметку «Хук завершения хода»): скрипту подаётся на
stdin тот JSON, который шлёт Claude Code, и сверяется код возврата.

ВАЖНО про пути в тестах: Git Bash подставляет POSIX-путь
(`/tmp/...`), а Python видит `CLAUDE_PROJECT_DIR` как `C:\...` —
для `relative_to` это разные деревья, и хук молча пропустит файл
как «вне проекта». В тестах путь собирать через `os.path.join`,
а не через `$PWD`.

## Конвенции кода

- Язык общения, комментариев и документации — **русский**.
- Шаблоны хуков пишутся на русском; имена переменных внутри них —
  тоже (так они читаются пользователем-непрограммистом).
- Пометки `[МАСТЕР: …]` в шаблонах — инструкции мастеру. При записи
  в проект их НЕ переносить.
- Строки, которые хуки сверяют между собой (фазы, ключи табло,
  статусы), должны совпадать буквально в `SKILL.md` и во всех
  шаблонах. Меняешь в одном месте — проверь остальные.
- Версия плагина живёт в ДВУХ местах: `plugin.json` и
  `templates/VERSION` (паспорт для ручных установок, когда
  манифест не копируется). Поднимаешь версию — меняй оба разом.

## Правила работы

- **Пользователь не программист** (базовые понятия). Объяснять
  решения обычными словами, без жаргона; техническую часть брать
  на себя. Предлагая вариант — называть последствия простым языком.
- Документацию Claude Code проверять по первоисточнику
  (https://code.claude.com/docs/en/hooks.md), а не по памяти:
  механика хуков меняется между версиями.
- Публикация: `git push` в публичный репозиторий — только по явной
  просьбе пользователя.
- Стиль общения: коротко, по делу, без воды. Сомневаешься — спроси.
