# Согласование через карточку вопроса

Статус: сделано
Дата: 2026-08-23
Коммит: 8fb6e30

## Проблема

Согласование заметки держалось на кнопке Run у bash-блока:
пользователь жмёт Run → `approve_task.py` ставит штамп в табло →
фоновый наблюдатель будит сессию. Схема работала неделю (14–22
августа, десятки согласований, где работа продолжалась сама), а
потом начала молча зависать.

Причина найдена 2026-08-23 и подтверждена тремя источниками.
**Кнопка Run не выполняет команду — она печатает её в терминал
приложения.** Терминал занят (в Self-org с 09:03 в нём стоял
`manage.py runserver 8010`) — текст уходит в стоящий процесс,
команда не выполняется, признаков нет, кнопка бесконечно
показывает «выполняется». Доказательства:

- живой опыт: нажатия в 09:18 и 09:21 — впустую; в 09:51, когда
  приглашение освободилось, та же команда отработала сразу;
- в записях сессии между показом блока и сообщением пользователя
  нет ни одного события, файл-маркер не создавался;
- в логах приложения за трое суток — ноль запусков команд из
  блоков при десятках нажатий.

Проверка «терминал занят» в приложении есть, но сделана через
POSIX-механизм (`ps -o tpgid`) и на Windows отключена: занятости
оно не видит и не предупреждает. Это дефект приложения, чинить
его не нам.

Отвергнутые ходы (для истории): памятка «держать вкладку
терминала свободной» — правило, которое надо помнить, а по
принципу 10 такому не место; слово-одобрение в чат плюс хук
на событие сообщения — работает, но это ещё одна надстройка
поверх сломанной схемы, и печатать слова пользователь не должен.

## Решение

Принцип: **согласование — это клик по варианту в карточке
вопроса** (инструмент AskUserQuestion). Карточка живёт в чате и
не зависит от терминала, вкладок и кнопок в кодовых блоках; ответ
в стенограмму пишет Claude Code, а не ассистент, — подделать его
он не может, честность штампа сохраняется. Ответ на карточку
возвращает ход ассистенту сам: будить сессию нечем и незачем.

Конструкция при этом уменьшается — новых хуков ноль:

а) `gate_edit.py`: вместо отметки `одобрено` в табло проверяет
   стенограмму (`transcript_path` приходит хуку на вход). Ищет
   запись ПОЛЬЗОВАТЕЛЯ, где есть название задачи из табло и
   вариант «Согласовано». Название в вопросе привязывает
   согласование к текущей задаче — старое «Согласовано» от
   прошлой задачи не засчитается.
б) `check_turn_end.py`: вместо трёх проверок (блок с командой,
   упоминание, наблюдатель) одна — в фазе «заметка» ход не
   заканчивается молча: либо карточка, либо вопрос в тексте.
в) `check_commit.py`: запрет ассистенту запускать штамп удаляется
   — запускать больше нечего.
г) `approve_task.py` — удаляется.
д) Фоновый наблюдатель за табло — удаляется из процедуры вместе
   с таймаутом и повторными призывами.
е) `SKILL.md`: шаг 3 переписан на карточку; таблица хуков — шесть
   файлов вместо семи; упоминания Run и штампа убраны.
ж) Версия 1.4.0 в `plugin.json` и `templates/VERSION`.

Поле `одобрено` в табло остаётся для человека (видно, что задача
согласована), но ни один хук на него больше не опирается.

Слабое место названо честно: проверка опирается на то, как Claude
Code записывает ответ пользователя в стенограмму. Формат
изменится — хук перестанет узнавать согласование и будет
блокировать правки, пока не поправим строку. Это видно сразу и
чинится одной строкой — в отличие от прежней тишины на десять
минут.

## Как проверим

1. `python -m py_compile` всех шаблонов.
2. Прогон `gate_edit.py` подачей JSON на stdin (методика из
   CLAUDE.md, пути через `os.path.join`): согласование по текущей
   задаче в стенограмме → правка кода проходит; согласование от
   ДРУГОЙ задачи → блок; стенограммы нет или файл битый → блок с
   понятным текстом; пустое табло → напоминание, не блок;
   `docs/` и `.claude/` → всегда проходят.
3. Прогон `check_turn_end.py`: фаза «заметка», согласования нет,
   ход кончается утверждением → возврат; тот же ход вопросом →
   тихо; согласование уже есть → тихо; малая форма → тихо.
4. Живьём — на настоящей стенограмме: функция обязана найти
   сегодняшний клик по «Согласовано» в этой сессии и не найти
   согласования для чужого названия задачи.

**Факт: 20 сценариев из 20 зелёные** (13 на `gate_edit.py`, 6 на
`check_turn_end.py`, плюс второй формат записи ответа). Проверка
на живой стенограмме этой сессии нашла запись клика
`4f69c0e5-c6fd-484e-a0a7-7500dcf86b28`; для чужого названия
задачи вернула «не найдено». `py_compile` всех шаблонов — чисто.
