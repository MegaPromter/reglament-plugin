# Хук завершения хода — требовать блок штампа, а не упоминание

Статус: в работе
Дата: 2026-08-22

## Проблема

Живой сбой в planapp_django (2026-08-22): ассистент завершил ход
призывом «нажмите Run на блоке выше», но блока с командой штампа
в ходе не показал — единственным блоком был вывод фонового
наблюдателя, у которого кнопки Run не бывает. Пользователю
некуда нажимать; ожидание штампа зависло.

Два слоя:

1. **В planapp_django хука нет.** Проект настроен старой версией
   плагина (v1.1): файла `check_turn_end.py` в `.claude/hooks/`
   нет, секции `Stop` в `settings.json` нет. Страховка не
   сработала, потому что не установлена. Проверено диффами:
   остальные хуки planapp функционально актуальны — v1.2/1.2.1
   меняли только Stop-хук.
2. **Дыра в самом шаблоне.** «Призыв прозвучал» определяется по
   подстроке `approve_task.py` в тексте хода. Кнопку Run даёт
   только отдельный bash-блок; упоминание скрипта в обычной фразе
   («наблюдатель запущен, после approve_task.py продолжу»)
   проходит проверку — а кнопки у пользователя нет. Честно:
   именно сегодняшний ход свежий хук поймал бы (подстроки не
   было), но ту же беду через упоминание без блока он не ловит.

Одноразовость хука (`stop_hook_active`) не трогаем — это
встроенная защита от цикла, так задумано.

## Решение

а) Шаблон `check_turn_end.py`: признак призыва — команда
   `approve_task.py` **внутри кодового блока** (текст делится по
   ` ``` `; нечётные куски — содержимое блоков). Инлайн-код в
   одинарных бэктиках блоком не считается — кнопки он не даёт.
   Новый порядок проверок:
   - команда в блоке есть → как раньше, проверка наблюдателя;
   - блока нет, ход кончается вопросом → тихо (согласование ещё
     идёт; не возвращаем дефект №1 прошлой правки);
   - блока нет, но `approve_task.py` упомянут → новый reason:
     команда упомянута, но не оформлена отдельным bash-блоком —
     кнопки Run не будет; оформи блоком и повтори призыв;
   - ничего нет → прежний общий reason.
   В обоих reason команда показывается сразу в оформлении
   ` ```bash `, чтобы ассистент копировал готовую форму.
б) `SKILL.md`, шаг 3: в описании хука «без призыва к штампу» →
   «без блока штампа» (формулировки сверяются буквально).
в) `plugin.json`: 1.2.1 → 1.2.2.
г) Доустановка в planapp_django (закрывает слой 1): копия нового
   `check_turn_end.py` в `.claude/hooks/` со снятой
   МАСТЕР-пометкой, секция `Stop` в его `settings.json` по
   образцу `templates/settings-hooks.json`. Подхватится со
   следующей сессии planapp.

Маркер 1 (доустановка: отсюда или отдельной задачей в planapp)
снят: согласован вариант А — отсюда, прецедент Self-org
(2026-08-22).

За рамками задачи: у мастера нет режима «обновить хуки в уже
настроенном проекте» — именно поэтому planapp отстал. Вынесено
в отдельную задачу (кнопка-задача «Режим обновления хуков у
мастера»).

## Как проверим

1. `python -m py_compile` шаблона (и установленной копии).
2. Прогон сценариев подачей JSON на stdin (методика из CLAUDE.md;
   пути собирать через `os.path.join`, не `$PWD`): 12 прежних —
   сценарий «призыв + наблюдатель — тихо» переписан на команду
   в блоке — плюс 3 новых: упоминание без блока в утверждении →
   блок «оформи блоком»; упоминание без блока в вопросе → тихо;
   команда только в инлайн-коде → блок «оформи блоком».
   Итого 15, все зелёные до коммита.
3. planapp_django: живому ходу не мешаем — по текущей задаче
   штамп уже стоит, в этом состоянии хук молчит.
