# Починки check_commit из planapp — в шаблон

Статус: сделано
Дата: 2026-08-23
Форма: малая

## Проблема

Обновляя planapp до 1.4.0, режим обновления нашёл в его копии
`check_commit.py` две правки, которых нет в шаблоне плагина. Их
писали по живым сбоям, но жили они только в одном проекте: каждый
новый проект получал от мастера версию с теми же граблями, а
следующее обновление могло их затереть.

1. **Слово «commit» ловилось где попало.** Шаблон искал вызов
   коммита регуляркой `\bgit\b[^|;&]*\bcommit\b` — под неё попадали
   `bash .claude/hooks/pre-commit-tests.sh`, ветка
   `feature/commit-helper` и любое упоминание в тексте сообщения.
   Хук требовал ссылку на заметку у команды, которая коммитом не
   была.
2. **Коммит в чужой репозиторий проверялся по чужому регламенту.**
   Работая в проекте А, ассистент коммитит в соседний репозиторий Б
   (например, в сам плагин) — и хук проекта А требовал ссылку на
   документацию проекта А.

## Решение

Перенести в `templates/check_commit.py` готовый и обкатанный код из
planapp, вернув шаблонные соглашения (константы `ПОМЕТКА_ЖУРНАЛА` и
`МЕТКИ_ИСКЛЮЧЕНИЯ`, пометки `[МАСТЕР: …]`, метка версии):

- `есть_вызов_коммита()` — разбор команды по токенам: токен `git`,
  затем токен ровно `commit`, между ними пропускаются глобальные
  ключи (`-C`, `-c`, `--git-dir`, `--work-tree`);
- `целевая_папка()` и `верх_репозитория()` — куда коммит попадёт на
  самом деле (учитывая `cd` и `git -C`) и в каком репозитории эта
  папка лежит. Чужой репозиторий — пропуск; неопределённость — в
  пользу проверки.

Версия 1.4.1 в `plugin.json` и `templates/VERSION`.

## Как проверим

Прогон сценариев подачей JSON на stdin, два временных репозитория
(свой и чужой): `pre-commit-tests.sh` → не коммит; `git checkout -b
feature/commit-helper` → не коммит; коммит без ссылки → блок;
`git -C чужой commit` → пропуск; `cd чужой && git commit` → пропуск;
`git -c ключ commit` → коммит распознан; ссылка на существующую
заметку → пропуск; на несуществующую → блок; метка-исключение и
пометка журнала → пропуск; запуск `approve_task.py` → больше не наше
дело.

**Факт: 11 из 11 зелёные**, `py_compile` чист.
