# Сборщик аудита прячет свой вывод от git

Статус: сделано
Дата: 2026-09-01
Форма: малая

## Проблема

`audit-raw.md` — рабочий файл сборщика, в репозиторий он не
нужен. Сборщик кладёт его в корень проекта и на этом всё:
строка в `.gitignore` не появляется, и каждый прогон засоряет
`git status`. Ровно так файл неделю провисел в этом
репозитории — замечен 2026-08-31, вычищен вручную коммитом
9d9a82c. В чужих проектах вычищать будет некому.

По принципу 10 «не забудь дописать строку» — инструкция
ассистенту, то есть временная мера. Место действия — сам
сборщик.

## Граница сборщика: уточнение, а не отмена

Заявлено в шапке `collect_audit.py` и повторено в заметке
«Навык аудита»: «Ничего не чинит, не ставит и не решает».
Запись в `.gitignore` эту формулировку нарушает — сборщик
правит файл проекта.

Формулировка уточняется: сборщик не чинит ЧУЖОЕ, но убирает
ЗА СОБОЙ. Строка в `.gitignore` относится только к его
собственному выходному файлу; всё остальное в проекте он
по-прежнему только читает. Правка вносится в оба места, чтобы
через полгода никто не считал это самоуправством скрипта.

## Решение

После записи отчёта — шаг «спрятать свой вывод»:

- в `.gitignore` пишется имя из ключа `--вывод`, а не жёстко
  `audit-raw.md`: иначе при своём имени файла строка окажется
  не про тот файл;
- шаг пропускается, если проект не под git (нет `.git`), если
  вывод лежит вне корня проекта или если строка уже есть;
- `.gitignore` отсутствует — создаётся;
- переносы строк существующего `.gitignore` сохраняются; нет
  перевода строки в конце — добавляется, иначе строки
  слипнутся;
- строка идёт с коротким комментарием: откуда она взялась;
- ошибка записи (права, файл только для чтения) — предупреждение
  в stderr и продолжение. Правило «сборщик не падает» сильнее.

Отдельно — ловушка, которую `.gitignore` не лечит: если
`audit-raw.md` УЖЕ закоммичен, игнорирование на него не
действует, git продолжает его отслеживать. Сборщик это
проверяет (`git ls-files`) и говорит, что делать
(`git rm --cached`), но сам ничего не удаляет: чужие файлы из
индекса вынимает пользователь.

Версия 1.4.6 в `plugin.json` и `templates/VERSION`.

Реализовано в коммите 79adb93 (2026-09-01), отправлено на
GitHub 2026-09-01 (`7ced3e9..3300f6f`).

## Как проверим

Прогоны на временных проектах:

1. git-проект без `.gitignore` → файл создан, строка на месте;
2. `.gitignore` есть, строки нет → дописана, прежнее
   содержимое цело;
3. строка уже есть → файл не изменился (сверка байт в байт);
4. `.gitignore` с windows-переносами → переносы не поехали;
5. `.gitignore` без перевода строки в конце → строки не
   слиплись;
6. проект без git → `.gitignore` не создан;
7. `--вывод своё-имя.md` → в `.gitignore` имя из ключа;
8. `--вывод` за пределами корня → `.gitignore` не тронут;
9. вывод уже отслеживается git → предупреждение с подсказкой
   `git rm --cached`, файл из индекса не вынут;
10. `py_compile` чист.

Сверх плана проверено: форма `/audit-raw.md` в `.gitignore`
тоже считается уже имеющейся; вывод в подпапке пишется прямым
слэшем (`docs/audit-raw.md`), а не windows-обратным; в чистом
репозитории предупреждения про индекс нет (ранняя версия
проверки принимала за имя файла текст ошибки git и тревожила
зря — ужесточено до сверки по строкам вывода).

**Факт: 18 из 18 зелёные.** Плюс сквозной прогон сборщика на
временном репозитории: отчёт записан, строка добавлена,
`git status` показывает только правку `.gitignore` — сам
`audit-raw.md` больше не виден.
