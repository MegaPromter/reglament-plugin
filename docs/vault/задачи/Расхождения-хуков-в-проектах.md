# Расхождения хуков в проектах: что общее, что личное

Статус: сделано
Дата: 2026-08-23

## Проблема

Копии хуков в planapp_django и Self-org разошлись с шаблонами
плагина. Часть расхождений — настоящие починки (перенесены в 1.4.1,
[[Починки-check-commit-из-planapp]]), часть — личные настройки
проекта. Пока это не разделено, режим обновления решает вопрос
заново на каждом файле, а общее продолжает жить в одном проекте и
умирает вместе с ним.

## Что нашлось

`validate_vault.py` в planapp: словари типов (+«техдолг»,
+«справка»), дата отсечки для секции «Как проверим», формулировки со
ссылками на номера правил их регламента.

`close_task.py` в planapp: вызов собственного `effort_log.py`,
список файлов вместо одного (нужен ради того же журнала), подпись
Co-Authored-By в закрывающем коммите.

Self-org: расхождений по сути нет — там установка v1.1 без меток
версии, всё лечится обычным обновлением.

## Решение

а) В шаблон переносится ОДНО — механизм даты отсечки для секции
   «Как проверим» (`ДАТА_ОТСЕЧКИ` в `validate_vault.py`). Правило
   «у каждой задачи есть „Как проверим“» вводят в проекте, где
   заметки уже лежат; без отсечки валидатор начинает валить коммиты
   за историю, которую никто не переписывал. По умолчанию пусто —
   требовать у всех, как и надо новому проекту. Пометка мастеру:
   ставя систему в проект с готовым vault, спросить дату внедрения.
   Заметка без поля «создано» при заданной отсечке считается старой.
б) Остальное признано личным и в плагин не идёт: словарь типов (у
   каждого проекта свой, мастер его и так адаптирует), `effort_log`
   — хук проекта, о котором плагин не знает, подпись в закрывающем
   коммите — дело проекта, формулировки с номерами правил — тоже.
в) Режим обновления, шаг 6: закреплено текстом то, что мастер уже
   делал по факту. Расхождение — не всегда отставание. Починка
   общего смысла сохраняется у проекта, и пользователю говорится,
   что её место в плагине (переносится отдельной задачей в
   репозитории плагина, иначе умрёт в одном проекте). Настройка
   проекта сохраняется как есть и в таблице состояния называется
   «ваши настройки», а не «устарело».
г) Версия 1.4.2.

## Как проверим

Сценарии `validate_vault.py`: задача без «Как проверим» при пустой
отсечке → нарушение; секция на месте → чисто; отсечка позже даты
создания → тихо; отсечка раньше → нарушение; нет поля «создано» при
заданной отсечке → тихо; прежние проверки (статус не из словаря,
«сделано» без хэша) работают по-старому. Плюс `py_compile`.

**Факт: 7 из 7 зелёные.** Заодно перепроверены прежние наборы:
20/20 по согласованию через карточку и 11/11 по контролёру коммита.
