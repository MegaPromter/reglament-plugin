# Регламент в самом репозитории плагина — средний вариант

Статус: сделано
Дата: 2026-08-18

## Проблема

Инструмент, который заставляет другие проекты работать по
процедуре, сам по ней не работал. В репозитории не было ни
устава `CLAUDE.md`, ни `.claude/`, ни хуков — только папка
`docs/vault/` с одной заметкой, созданной по ходу задачи
про хук завершения хода.

Практическое следствие: заметку и согласование по той задаче
ассистент вёл вручную, «на честном слове». Забыл бы — никто
бы не остановил. Ровно та забывчивость, против которой
написан принцип 10.

## Рассмотренные варианты

**Полный регламент** (как в других проектах): устав, vault,
табло задачи, семь хуков принуждения.
За: инструмент проверяется на себе, кривизна мастера всплывает
на своей работе раньше, чем у пользователя.
Против: репозиторий-шкатулка, автотестов нет, правки редкие;
процедура из семи хуков тяжелее самой работы. Плюс путаница —
рабочие копии хуков в `.claude/hooks/` рядом с шаблонными в
`templates/`, легко перепутать при правке.

**Ничего не делать.** Против: решения по плагину нигде не
фиксируются, каждая следующая задача начинается с нуля.

**Средний вариант (выбран):** устав `CLAUDE.md` + структура
`docs/vault/`, без табло и хуков.

## Решение и обоснование

Ценность здесь — в том, чтобы решения по плагину были
записаны (почему `stopReason` не подошёл, почему свой флаг
в табло не завели, почему тесты путей ломались в Git Bash),
а не в блокировке правок: репозиторий единоличный, автор он
же ревьюер. Принуждение держится на правилах устава.

## Что сделано

- `CLAUDE.md` — устав: облегчённый регламент из 7 пунктов
  (принцип 10 вынесен как главный для этого репозитория),
  структура проекта с пояснением «`templates/` — заготовки
  для чужих проектов, здесь не исполняются», ручная проверка
  шаблонов, конвенции, правила работы.
- В устав внесены два знания, добытые прошлой задачей:
  проверять документацию Claude Code по первоисточнику, а не
  по памяти; в тестах хуков собирать путь через `os.path.join`,
  а не через `$PWD` (Git Bash даёт POSIX-путь, Python видит
  Windows-путь, `relative_to` считает файл «вне проекта» и
  хук молча пропускает).
- `docs/vault/задачи/` — папка приведена к строчной букве,
  как в других проектах (было `Задачи`), через `git mv` в два
  шага: Windows нечувствителен к регистру, прямое
  переименование git не замечает.
- `docs/vault/_meta/` — создана под будущий регламент.

## Чего сознательно НЕ сделали

Табло `task-state.json` и хуки принуждения. Если окажется, что
правил устава мало — ставится полный вариант мастером; работа
уже разложена так, что это не потребует переделок.

## Как проверим

Следующая задача по плагину начинается с чтения vault и
заметки до кода — без напоминаний со стороны пользователя.
Если снова понадобится напоминать, значит среднего варианта
мало и нужен полный.
