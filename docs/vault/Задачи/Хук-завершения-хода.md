# Хук завершения хода — контроль незавершённых шагов

Статус: в работе
Дата: 2026-08-17

## Проблема

Шаг «поставить наблюдателя после Run» описан только текстом в
навыке. Текст ассистент читает в начале сессии и забывает
к середине. Это воспроизводимо и не лечится формулировкой:
нельзя написать «не забывай» так, чтобы стало нельзя забыть.

## Решение

Хук на событие `Stop` (ассистент закончил ход). Скрипт
`check_turn_end.py`:

1. Читает `.claude/task-state.json`.
2. Если фаза «заметка», штампа `одобрено` нет и флага
   `напомнил` нет — блокирует завершение хода и возвращает
   ассистенту указание вывести пользователю явный призыв
   нажать Run. Ставит в табло `напомнил: true`.
3. Если во входном JSON `stop_hook_active: true` — сразу
   пропускает. Это ВСТРОЕННАЯ защита от цикла: Claude Code
   сам выставляет флаг, когда ход уже был развёрнут хуком.
   Свой флаг в табло не нужен и вреден — он может застрять
   выставленным, если сессия оборвётся посреди хода.

## Проверенные механики (docs/en/hooks)

- Блокировка: stdout `{"decision": "block", "reason": "..."}`.
  Для `Stop` текст `reason` **передаётся ассистенту как
  следующая инструкция** — это нужный нам канал.
- НЕ использовать общее поле `stopReason`: по документации
  оно «Not shown to Claude», показывается только пользователю.
- `stop_hook_active` во входном JSON — встроенный страж цикла.
  После 8 подряд блокировок Claude Code перебивает хук сам.
- У события `Stop` нет поддержки `matcher` — поле молча
  игнорируется. Регистрация без него.
- `Stop` не срабатывает на прерывание пользователем (Esc);
  на ошибках API срабатывает отдельное событие `StopFailure`.

## Что меняется в файлах

- новый шаблон `templates/check_turn_end.py`;
- `templates/settings-hooks.json` — секция `Stop`;
- `SKILL.md` — упоминание нового хука в шаге установки хуков.

`approve_task.py` править НЕ нужно: собственного флага не
заводим, сбрасывать нечего.

## Как проверим

На тестовом проекте: завести задачу, довести до фазы
«заметка», закончить ход без призыва к Run — хук должен
развернуть ассистента один раз. Второй раз в том же
состоянии — не должен. После `approve_task.py` флаг сброшен,
при следующей задаче механизм работает снова.

## Уточнить

Формат, в котором Stop-хук возвращает блокировку в текущей
версии Claude Code. Проверяется первым делом при реализации.
Если блокировка недоступна — вернуться к пользователю с тем,
что реально возможно, а не подгонять под замысел.

## Связанные

Принцип 10 регламента: всё, что ассистент обязан делать
регулярно, выносится в скрипт-хук.
