# Навык уборки памяти (ДСХ)

**Язык общения:** сначала обычное слово, в скобках — имя из кода («текущий статус
(`Текущий статус.md`)»). Нельзя согласовать то, что непонятно.

**Что это.** Память проекта (`.dsh/memory/`) — быстрая рабочая копия знаний; оригинал
живёт в vault (`docs/vault/`), память — только кэш и в git не попадает. Со временем
кэш засоряется: статус разрастается, один факт появляется в двух файлах, числа
расходятся с фактом, ссылки указателя ведут в никуда. Правило и признаки — ADR
«Подсказка об уборке памяти». Этот навык механизирует уборку: **считает измеритель,
решает пользователь, правит ассистент**.

Пороги (сколько строк статуса — много, сколько дней с уборки — пора) живут в
измерителе, `.dsh/tools/memory_check.py`, одним местом. Здесь они не повторяются:
меняются правкой измерителя и записью в ADR, а не правкой текста навыка.

## Два входа — не путать

| Вход | Что делает ассистент |
|---|---|
| проверка (в том числе на закрытии задачи) | запускает измеритель, показывает отчёт с числами. Ничего не меняет |
| уборка — по слову пользователя «уборка памяти» | то же плюс копия памяти и сами правки |

**Молча память не чистится.** Отчёт без слова пользователя — только отчёт: подсказка
называет причину, решение остаётся за человеком. Отказ ничего не ломает — подсказка
вернётся на следующем закрытии задачи.

## Проверка (шаг 1 — всегда)

Запустить измеритель окружением проекта:

```
.\venv\Scripts\python.exe .dsh\tools\memory_check.py
```

Он печатает числа по каждому признаку и в конце — «ИТОГ: причин N» (код выхода 1,
когда причины есть). Показать пользователю **числа, а не выводы**: «статус 120 строк
при пороге 100», «число 1887 тестов в двух файлах», «кандидатов в дубли: 3».

Полный список количеств (тесты, строки, файлы, размеры, проценты) — ключом `--числа`;
он нужен на уборке, когда числа сверяются с фактом.

**Подсказка на закрытии задачи** — одна строка по шаблону ADR:

> Пора убрать память: <причина с числом>. Скажите «уборка памяти» — сведу дубли,
> починю указатель и покажу, что изменилось.

Причин нет — подсказки нет: молчание означает «всё в порядке». Всегда подсказываем
перед передачей работы и перед переездом в закрытый контур, а также вне очереди —
если ассистент ошибся из-за памяти (взял не тот порт, сослался на отменённое правило).

## Уборка (шаг 2 — по слову пользователя)

Порядок обязателен: сперва копия, потом правки.

1. **Копия.** `.\venv\Scripts\python.exe .dsh\tools\memory_check.py --копия` —
   папка `.dsh/memory-backup-<дата>` рядом с памятью. Память не в git: без копии
   ошибку уборки откатить нечем. Копия с таким именем уже есть — кладётся рядом
   следующая: перед каждой уборкой копия должна быть свежей.
2. **Дубли** — свести: факт остаётся в одном месте (там, где ему быть по смыслу), в
   остальных — ссылка на это место. Одинаковые количества («1887 тестов») — тот же
   случай: число живёт в одном файле.
3. **Устаревшее** — убрать: отменённые договорённости, снятые пометки, закрытые
   хвосты. Числа сверить с фактом: прогон тестов, размер файла, версия в слепке
   зависимостей. Число, которое «вроде такое», не оставляем — берём из факта.
4. **Указатель и статус** — починить: каждый файл памяти упомянут в «Индексе»
   (`Индекс.md`), ссылки ведут на существующие файлы, статус короткий (подробность —
   в отдельный файл «Ход работ — …», как это уже сделано для переноса).
5. **Пометки «в ДСХ этого нет»** — снять устаревшие: возможность завели или убрали
   — пометка врёт. Заведённое переносим строкой в заметку vault «Чего не хватает в
   ДСХ — опись пробелов» (или вычёркиваем оттуда, если закрылось).
6. **Дата уборки** — обновить строку «уборка памяти: дата» в «Текущем статусе»: по
   ней считается признак «с уборки больше месяца».
7. **Проверка после уборки:**
   - измеритель снова — причин быть не должно;
   - стражи: `.\venv\Scripts\python.exe -m pytest tests/test_dsh_memory_guard.py tests/test_dsh_skills_guard.py -q` — зелёные.
8. **Показать, что изменилось** — перечень файлов и суть правок, «до и после» (git
   тут не помощник: память вне репозитория). Копия из шага 1 остаётся на месте.

## Границы (чего навык НЕ делает)

- Не чистит молча и не чистит по своей инициативе: без слова пользователя — только
  отчёт.
- Не правит vault: найденное там — отдельная задача по регламенту (навык «reglament»).
- Не удаляет спорное: сомнение — вопрос пользователю, а не решение за него.
- Не трогает файлы вне `.dsh/memory/` (кроме копии рядом с ней).
- Не заменяет стражей: они остаются последним рубежом независимо от уборки.
- Не ведёт замер усилия и не пишет в журнал мелких правок: уборка памяти — правка
  кэша вне git, коммита у неё нет.

## Проверки

```
.\venv\Scripts\python.exe .dsh\tools\memory_check.py
.\venv\Scripts\python.exe -m pytest tests/test_dsh_memory_guard.py tests/test_dsh_skills_guard.py -q
```

Команды в ДСХ могут потребовать подтверждения. Отказ не обходится: доложить и
спросить, а не искать другую оболочку.
